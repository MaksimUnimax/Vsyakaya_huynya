# R2 — Алкогольные лицензии / заявления как ранний HoReCa-сигнал

## Статус

`RESEARCH_NOT_STARTED_FULL_PASS`

Текущая стадия: гипотеза и методика зафиксированы. Коммерческий вывод не принят.

## Основная гипотеза

Процесс получения алкогольной лицензии по конкретному месту деятельности может сигнализировать о новой точке общепита или новом месте существующей сети до фактического открытия.

Критический вопрос: **публично ли виден этап заявления достаточно рано**, либо наружу попадает только уже выданная лицензия, когда большинство закупок и подрядчиков выбраны.

Если публичен только поздний факт выдачи, R2 может оказаться не самостоятельным продуктом, а подтверждающим/квалифицирующим сигналом для R1.

## Ключевые исследовательские вопросы

### 1. Полная lifecycle-цепочка

Построить фактическую последовательность:

`уведомление о начале общепита -> заявление на алкогольную лицензию -> рассмотрение -> решение -> выдача -> включение конкретного места -> фактическое открытие/алкогольные продажи`

Для каждого этапа установить:

- обязательность;
- официальный authority;
- timestamp;
- публичность;
- машиночитаемость;
- региональные отличия.

### 2. Что публично до выдачи

Отдельно исследовать:

- реестры заявлений;
- журналы поступивших заявлений;
- решения комиссий;
- региональные порталы лицензирующих органов;
- Москва;
- Санкт-Петербург;
- несколько регионов для сравнения;
- федеральный сводный реестр;
- open-data/API/export возможности.

Главная развилка:

- `APPLICATION_VISIBLE_EARLY` — высокий потенциал;
- `ONLY_ISSUED_LICENSE_VISIBLE` — существенно меньший потенциал.

### 3. Полный data dictionary

Для заявления/лицензии проверить наличие:

- дата подачи заявления;
- дата решения;
- дата выдачи;
- дата начала/окончания действия;
- ИНН/ОГРН;
- название;
- адрес конкретного места деятельности;
- КПП;
- тип лицензируемой деятельности;
- добавление нового места к существующей лицензии;
- исключение места;
- приостановление/аннулирование;
- координаты, если доступны;
- история изменений;
- идентификатор документа/реестровой записи.

### 4. Реальный lead time

Для выборки минимум 200–300 новых/добавленных мест определить:

- `application_to_opening`, если дата заявления доступна;
- `issue_to_opening`;
- `start-activity-notice_to_license` — при сопоставлении с R1;
- `license_to_first_review`;
- `license_to_public_opening_post`.

Результат нужен отдельно для:

- ресторанов;
- баров;
- кафе;
- сетевых точек;
- независимых заведений.

### 5. Новый объект или бумажное изменение

Классифицировать:

- `NEW_HORECA_BUSINESS`;
- `EXISTING_CHAIN_NEW_LOCATION`;
- `RELICENSE_EXISTING_LOCATION`;
- `ADDRESS_CHANGE`;
- `LICENSE_EXTENSION`;
- `SUSPENSION_OR_RESTORE`;
- `DUPLICATE`;
- `UNKNOWN`.

Нужен precision именно для **новых физических точек**.

## Сравнение R2 против R1

Обязательная часть исследования.

Для одних и тех же HoReCa-точек сравнить:

- когда появляется R1 уведомление;
- когда появляется заявление/решение/лицензия R2;
- какой источник даёт больше полей;
- какой источник точнее подтверждает реальное открытие;
- какой источник появляется раньше;
- какой источник даёт меньше шума.

Возможные исходы:

1. R2 раньше R1 — самостоятельный сильный продукт.
2. R1 раньше, R2 повышает confidence — R2 становится enrichment layer.
3. R2 поздний и ничего не добавляет — `KILL` как отдельное направление.

## Competition research — обязательный блок

Искать не только SaaS.

### Прямые

- коммерческие базы алкогольных лицензий;
- базы новых ресторанов/баров;
- HoReCa lead providers;
- поставщики данных ЕГАИС;
- отраслевые сервисы, продающие открытия новых точек.

### Косвенные

- 2ГИС/Яндекс Карты;
- Restaurant.ru / отраслевые медиа и каталоги;

- базы юрлиц;
- дистрибьюторские внутренние системы;
- алкогольные оптовики;
- геоаналитические сервисы;
- агентства по лидогенерации для HoReCa.

Для каждого выяснить:

- источник;
- скорость;
- публична ли дата заявления;
- конкретный адрес точки;
- контакты;
- цена;
- география;
- API/Telegram/email/CRM;
- кому продают;
- эксклюзивность;
- насколько легко получить тот же лид другим путём.

Особое исследование: **имеют ли крупные алкогольные дистрибьюторы уже автоматический доступ к новым лицензиатам**. Если да, это может убить значительную часть рынка покупателей.

## Commercial experiment

Если ранний signal существует:

1. выбрать город;
2. собрать 30–50 реально новых HoReCa-точек;
3. доказать lead time;
4. дать список нескольким поставщикам одной категории;
5. измерить готовность платить за такой поток и желаемый формат.

Не спрашивать абстрактно «интересно ли». Показывать реальные текущие лиды.

## Возможный MVP

Если R2 `GO` самостоятельно:

`application/license collector -> new-location detector -> HoReCa classifier -> dedupe -> Telegram/CSV`

Если R2 только enrichment для R1:

`R1 candidate -> R2 license confirmation -> confidence score`

## Kill criteria

`KILL` как самостоятельную идею, если:

- публично видна только выданная лицензия;
- выдача в большинстве случаев происходит после/слишком близко к открытию;
- R1 стабильно даёт тот же объект раньше;
- новые физические места трудно отличить от переоформлений;
- основные потенциальные покупатели уже получают те же данные автоматически;
- публичный источник нестабилен/непригоден для регулярного read-only получения.

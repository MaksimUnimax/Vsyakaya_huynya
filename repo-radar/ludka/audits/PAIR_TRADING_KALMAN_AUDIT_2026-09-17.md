## 1. What the repository claims

The notebook first performs Engle-Granger cointegration tests on 288 within-sector stock pairs and applies Benjamini-Hochberg FDR at q=0.05.

Result: **0 pairs survive**.

The notebook then does not stop. It explicitly:
- excludes the entire Tech sector (`EXCLUDE = {"Tech"}`) with a comment that the 2023–2025 AI boom inflates results;
- ranks the remaining pairs by **raw**, unadjusted Engle-Granger p-value;
- takes the top five anyway: `V/MA`, `KO/PEP`, `COST/LOW`, `COP/MPC`, `BAC/PNC`;
- runs both static and Kalman strategies on those five.

So the Kalman result is not evidence that Kalman discovered a relationship where none existed. The strategy is still pre-screened on the five most relationship-looking pairs despite the formal FDR null.

## 2. What Kalman actually does here

The model estimates a moving relationship:

`A_price ~= alpha_t + beta_t * B_price`

Static pairs trading uses one/frequently refitted beta. Kalman lets `alpha_t` and `beta_t` change every day as new prices arrive.

That can be useful for hedge sizing. It is **not** itself a source of trading PnL.

If beta changes while both stock prices are unchanged, a real trader has earned nothing. A backtest must therefore compute PnL from the price changes of the actual long/short holdings, with any re-hedging treated as turnover/cost.

## 3. The critical bug

The repository's `compute_kalman_returns()` constructs each day's fitted spread using the current lagged fitted `alpha` and `beta`, then takes:

`spread.diff()`

as the economic spread return.

But the difference between two consecutive fitted spreads contains two different things:

1. real movement in stock A and stock B;
2. **movement in the model's own alpha and beta**.

The second component is not money.

In algebraic form, with fitted spread

`S_t = A_t - alpha_t - beta_t B_t`,

then

`S_t - S_{t-1}`

contains terms proportional to `-(alpha_t-alpha_{t-1})` and `-(beta_t-beta_{t-1})*B_{t-1}`. Those are changes in the ruler used to measure the pair, not cashflows generated by a held position.

This is especially dangerous because the Kalman update moves alpha/beta in response to the same innovation that generates the trading signal. The model mechanically pulls its own residual toward zero, and the backtest books part of that model refit as if the market had mean-reverted.

### Toy example

Suppose:
- stock A stays at $100;
- stock B stays at $100;
- yesterday beta=1.00;
- today the Kalman estimate changes beta to 0.90;
- ignore alpha for simplicity.

No market price moved. A real long/short position earns $0.

But the fitted spread changes from:

`100 - 1.00*100 = 0`

to:

`100 - 0.90*100 = 10`.

A backtest using `spread.diff()` can see a $10 movement even though the market did nothing. That is phantom PnL from changing the model.

## 5. Correct self-financing PnL

We kept the same five pairs, same Kalman states and same entry/exit signals, but changed only the PnL accounting:

- PnL comes from `dA - beta_known * dB` for the actual tradable legs;
- alpha is not tradable and cannot create PnL;
- changing beta is not itself PnL;
- the first comparison intentionally keeps the author's entry/exit cost convention so the accounting defect is isolated.

Result:

## 6. Dynamic-beta turnover is secondary

A second sensitivity added incremental transaction cost when an already-open position must re-hedge because beta changes.

Corrected result with this additional turnover cost:

- Sharpe **-0.337**;
- total **-2.14%**;
- maxDD **-6.57%**.

This barely differs from the corrected no-rehedge-cost result. Therefore the collapse is **not** mainly a commission/slippage issue. It happens because the original backtest monetizes model refitting.

## 7. Why the portfolio Sharpe looked so strong

The gain was not broad across all five pairs.

The stored notebook itself shows:
- `KO/PEP`: no Kalman trades/results;
- `BAC/PNC`: effectively no contribution in the stored notebook output;
- `V/MA`: modest;
- `COP/MPC`: positive;

Our independent reconstruction confirms `COST/LOW` is the main phantom: the same signal path changes from roughly +233% to -14% when PnL is self-financing.

## 8. Additional methodological concerns

### Formal null ignored in pair selection

Zero pairs survived FDR, but the notebook still uses the five smallest raw p-values. This may be a useful exploratory screen, but it cannot be presented as if statistical significance survived.

### Post-hoc Tech exclusion

The notebook comments that Tech is excluded because the 2023–2025 AI boom inflates results. That rationale explicitly references the test-era regime and creates post-selection risk.

### Execution timing

Signals are placed into the next row, but the return formula is close-to-close. A literal next-day-open execution is not modeled with open prices, so there is still an execution-timing mismatch even after the main PnL defect is fixed.

### Fixed Kalman delta

`delta=1e-4` is chosen rather than estimated. The notebook itself acknowledges that likelihood/EM calibration would be more principled.

## 9. Plain-language verdict

The Kalman filter itself is not fraudulent or useless. It is a legitimate online estimator of a changing hedge relationship.

What failed here is the translation from **a changing statistical model** into **trading profit**.

The backtest effectively said:

> “my estimate of the relationship moved toward the observed prices, therefore the trade made money.”

But a trader only makes money when the prices of the securities held move in a favorable way. Changing the fitted relationship is not a cashflow.

Therefore the published Sharpe ~4 / maxDD ~0.67% headline should be treated as **invalid under correct PnL accounting**.

The repo remains useful as an educational example of how a sophisticated method can create very convincing phantom alpha when the accounting is not self-financing.

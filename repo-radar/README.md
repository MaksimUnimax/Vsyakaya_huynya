# Repo Radar

Отдельная игровая/исследовательская линия: поиск публичных GitHub-репозиториев, которые снаружи выглядят скучно, непонятно или непропорционально скромно, а внутри содержат заметно более серьёзный, необычный или амбициозный проект.

Это НЕ часть основных исследований репозитория `Vsyakaya_huynya`. Каталог `repo-radar/` изолирован от `research/` и не должен менять, блокировать или переопределять основную работу.

## Что мы ищем

Нас интересуют не только AI, маркетплейсы или API. Область может быть любой: инженерия, биотех, финансы, графика, новые интерфейсы, распределённые системы, наука, робототехника, хранение данных, инструменты для людей, необычные бизнес-модели и т.д.

Главная гипотеза игры: иногда автор долго ведёт важный для себя проект непублично, а когда проект становится зрелее или дороже в разработке, часть работы появляется в public. При этом автор может оставить очень нейтральное название, пустое описание или публиковать только часть системы. Это только гипотеза: намерение автора нельзя объявлять фактом без прямых публичных свидетельств.

## Файлы

- `DETECTOR.md` — правила и признаки поиска, методика проверки и шкалы.
- `CANDIDATES.md` — журнал уже просмотренных репозиториев, включая слабые и отклонённые. Он нужен в том числе для защиты от повторного поиска одного и того же.
- `WATCHLIST.md` — проекты, за развитием которых следим. Сюда кандидат попадает ТОЛЬКО после прямой команды владельца.

## Правило описания для владельца

Владелец проекта не программист. Для каждого кандидата сначала объяснять простыми словами:

1. что это за штука;
2. что она делает для человека/компании/системы;
3. почему идея необычна или может быть важна;
4. какие есть признаки непрозрачной публикации или public/private-разделения;
5. что мы пока НЕ знаем и где есть риск ошибочной интерпретации.

Технические термины допустимы только после простого объяснения.

## Базовое правило честности

`generic name + empty description` не означает маскировку. `молодой repo + много кода` не доказывает, что он раньше был private. `public mirror` не означает коммерческий секрет. Мы фиксируем наблюдаемые признаки отдельно от гипотез.

## Обновление

После каждого содержательного поиска:

- каждый реально просмотренный кандидат сразу заносится в `CANDIDATES.md`;
- повторно не исследуется без нового сигнала или заметного развития;
- пользователь сам решает, кого переносить в `WATCHLIST.md`;
- для watchlist при будущей проверке сравнивается состояние с датой последнего просмотра, а не проводится полный поиск с нуля.

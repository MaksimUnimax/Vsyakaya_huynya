# Repo Radar — Watchlist

Здесь хранятся только проекты, за развитием которых владелец явно решил следить.

**Важно:** ассистент НЕ переносит кандидатов сюда самостоятельно, даже если считает их очень интересными. Добавление — только после прямой команды владельца вроде: `внеси RR-003 в наблюдение`.

Сейчас watchlist **пуст по замыслу**.

## Что фиксировать при добавлении

Для каждого выбранного проекта:

- Repo / URL.
- Candidate ID из `CANDIDATES.md`.
- Почему владелец решил наблюдать.
- Baseline date — дата, с которой отслеживаем изменения.
- Baseline facts — 3–8 важных фактов о текущем состоянии.
- Что именно смотреть дальше: новые релизы, архитектурные изменения, продукт, коммерциализация, рост stars, переходы public/private, новые связанные repo, подтверждение/опровержение ключевой идеи.
- Last checked.
- Change summary — только то, что изменилось с прошлого просмотра.

## Шаблон

```md
### W-XXX — `owner/repo`

- Candidate: RR-XXX
- URL: https://github.com/owner/repo
- Added: YYYY-MM-DD
- Last checked: YYYY-MM-DD
- Почему наблюдаем: ...
- Baseline:
  - ...
  - ...
- Следить за:
  - ...
- Изменения:
  - YYYY-MM-DD — ...
```

## Правило будущих проверок

Для watchlist не начинать исследование с нуля. Сначала читать эту карточку и соответствующую запись в `CANDIDATES.md`, затем сравнивать текущий GitHub с `Last checked`/baseline. Полный повторный аудит нужен только если проект сильно изменился.
